# 电商视频生成 Agent 定稿

日期：2026 年 10 月 9 日  
状态：定稿  
取代：`docs/superpowers/specs/2026-10-08-ecommerce-video-agent-design.md`

本版只实现核心视频生成，并用一个简单的桌面测试程序验证。Web 工作台、登录、权限、费用和页面由后续接入方负责。接入时直接调用本仓库的 Python 包，本版不提供 HTTP 服务。

初稿里已经确认的生成规则仍然有效：方案先于成片、时长只能选档、指定首帧才能导出成片、可选字幕/配音/音乐、整条和按镜头重生成、主体与场景连续。本文只改交付边界和验证方式，不重开这些规则。

## 目标与范围

做一个 Python 包 `video_agent`。它接收产品资料、产品图片和视频要求，先规划脚本与分镜，经调用方确认后，调用视频模型生成画面，再按开关完成字幕、配音、音乐和成片导出。

同一仓库再做一个桌面测试程序。它只负责把上述能力走通：登记图片、填写要求、查看和修改方案、确认、看进度、打开成片、重试和重生成。它不是工作台，也不复制工作台里已有的页面。

| 本版交付 | 本版不做 |
| --- | --- |
| `video_agent` 核心包：规划、确认、生成、合成、状态、本地存储 | HTTP、Webhook、WebSocket、鉴权 |
| 桌面测试程序：单机操作上述流程 | Vue 页面、登录、业务权限、费用和预算 |
| 模型、媒体、存储通过 Python 接口注入 | 多供应商智能路由 |
| 替身模型跑通成片导出；配置了真实服务后再出真实样片 | 首帧生图。只留调用边界，后续对接 imageAgent |
| 本地 SQLite 和本地文件 | 对象存储、远程拉图、多执行器部署 |

产品还原要求：主要外观和识别特征保持一致，允许轻微细节偏差。包装小字不承诺逐字复刻。明显影响识别的 Logo 或包装变化要在质量结果里标出。文字卖点放在可选字幕层，不依赖视频模型写出准确文字。

商品品类不限制为一种。流程对所有品类相同。生成质量按品类用真实样片看，不把“能跑通流程”写成“每个品类效果一致”。

## 交付物

```text
video_agent/          核心包。桌面程序和以后的工作台都只调用这里
desktop_app/          Tkinter 测试程序，进程内使用核心包
```

运行环境：Python 3.11+，Pydantic v2，本机可执行的 FFmpeg。桌面程序使用标准库 Tkinter，面向 Windows。成片用系统默认程序打开。

不引入 Agent 编排框架。任务状态、方案版本和外部任务号只存在本包的任务库里。模型只负责理解产品、写方案、解释自然语言修改，以及按约束产出视频、配音等结果。

数据目录默认是进程当前目录下的 `.video-agent/`，可用环境变量 `VIDEO_AGENT_HOME` 改掉。其中包含 `agent.sqlite`、素材、中间文件、成片和本地 `config.json`。密钥只放在这个配置里，不进仓库。

目录不存在时自动创建。没有 `config.json` 时写入默认内容：模式为 `fake`；时长档为 5、10、15、30 秒，默认 10 秒；图片最多 12 张；单文件 20 MB；视频码率 8 Mbps；音频码率 192 kbps；分辨率使用导出预设表；规划、视频、配音、音乐的 `adapter` 为 `fake`；视觉检查的 `adapter` 为 `none`。仓库忽略 `.video-agent/`。本版没有删除任务的方法，任务和幂等记录都留在这个目录里。

已有配置读不出来，或违反后文的档位和尺寸规则时，进程拒绝使用这份配置，并且不改写原文件。覆盖某一档的宽高时，宽和高都必须是正偶数，比例必须仍是该档；不能增删比例档。图片张数和单文件上限只能比默认更小。设置对话框不编辑码率、分辨率、张数和单文件上限。

## 架构

状态变更只写在 `video_agent` 内。桌面程序调用这些方法并展示返回值，不自己维护第二套状态，也不直接调用视频供应商。

| 模块 | 职责 | 依赖 |
| --- | --- | --- |
| 任务服务 | 登记素材，创建和修改方案，确认，重生成，重试，查询 | 任务库、规划接口 |
| 规划器 | 把资料和图片变成可执行方案；解释自然语言修改 | 规划模型接口 |
| 生成执行 | 确定首帧，逐镜生成，导入结果，按开关处理音频和字幕，导出 | 视频模型接口、配音接口、音乐接口、FFmpeg |
| 任务库 | 保存任务、方案、镜头、执行、成品、幂等记录 | SQLite |
| 文件库 | 按任务和执行分目录保存字节 | 本地目录 |
| 单工人 | 领取已落库的工作，续租，执行一步，启动时恢复中断任务 | 任务服务 |
| 桌面测试程序 | 表单、方案查看、进度和打开成片 | 任务服务、单工人 |

换视频模型时，任务服务的方法签名保持不变。规划模型、视频模型、配音、音乐、视觉检查、任务库和文件库都在构造时注入。本版文件库就是本地目录，成片通过本地路径读取。以后若换成对象存储，只替换文件库，调用方改为读取字节。

本版只运行一个工人线程。桌面程序启动时先 `recover()`，再循环调用 `tick()`；没有工作或仍在等待时休眠 1 秒。测试可以不启动线程，直接调用这两个方法。多个工人进程不在本版范围内。

领取按进入可执行状态的时间从早到晚，一次一条。写入 `pending` 或视频执行时，把当时的模式和五项适配器配置抄进这次工作。之后保存的新配置只影响新的规划和执行。`retry_planning`，以及还没有外部任务号的执行重试，按重试当时的配置重新抄一份。已经有外部任务号的查询和下载，仍用提交该任务时抄下的配置。

## 桌面测试程序

窗口标题为「视频生成测试台」。一个主窗口，四块区域：

1. 顶栏：数据目录、FFmpeg 是否可用、模式（替身 / 真实）、设置。
2. 左侧：本地任务列表。选中后加载该任务。
3. 中间：当前任务的需求、方案、执行。
4. 底部：最近一次错误的 `code`、`message`、`stage`。失败时展示这些字段，不用笼统的“失败”。

模式：

- `fake`：规划、视频、配音、音乐固定用包内替身，视觉检查固定为 `none`，不读配置里的适配器名，也不需要供应商密钥。替身视频只把 9:16 视为原生比例，其他预设比例在方案里写成 `pad`，确认前可以改成 `crop`。片段以该镜头要用的首帧或参考图为画面，帧数与方案一致，合成和成片检查仍走真实 FFmpeg。配音和音乐开启时，替身生成符合编码要求的音轨。
- `real`：按配置里五项 `adapter` 构造。规划和视频必须是已实现的真实适配器，不能是 `fake` 或 `none`，且必填项齐全。否则切换失败并说明缺什么，不改原配置，任务保持原状态。配音和音乐可以是真实适配器、`fake` 或 `none`。视觉检查可以是真实适配器或 `none`。

设置是主窗口上的对话框。它编辑时长档位、默认时长、当前模式，以及规划、视频、配音、音乐、视觉检查各自的 `adapter` 名和该适配器的必填项。保存只更新这些字段。码率、分辨率、张数上限、单文件上限，以及本次留空的密钥，都保持文件里的原值。对话框不回显完整密钥。保存结果不合法时不写入。内置适配器名只有 `fake` 和 `none`。真实适配器在实现时按当时选定的一家服务命名，并自行声明 `base_url`、`api_key`、`model` 等字段。本文不规定这家服务的报文。`fake` 模式下可以预先填写这些字段，切到 `real` 后才生效。

需求区字段：产品名称、品类、卖点、规格、自由描述、时长档位、画面比例、字幕、配音、音乐、配音语言或偏好、音乐说明或本地音乐文件、产品图片、首帧。图片从本机选择，最多 12 张。首帧是这些图片中的一张；另有一项「不指定首帧」，用来验证未实现路径。

方案区展示当前 head：创意、卖点、共享视觉设定、每个镜头的标识、内容、动作、景别、运镜、场景、帧区间，以及首帧来源、比例适配、三个开关。可以改档位、比例、开关、首帧和镜头文案，也可以填一句自然语言修改。按钮：提交修改、确认当前方案、放弃未确认草稿。

执行区展示 `stage`、已完成镜头数、总镜头数和阶段说明。阻塞问题显示在中间区域，不写成底部的执行失败。成品按版本从新到旧列出，显示时长、尺寸、质量结果，并提供「打开成片」。另有：整条重生成、按镜头重生成、重试失败的规划、重试失败的执行。按镜头重生成默认以最新一条成功成品为基础，由用户勾选镜头；没有成功成品时不可点。规划失败且还没有方案版本时，需求区仍可修改并通过补充信息重新规划。

按钮是否可点，只根据当前任务状态和本文的写入表。一次点击对应一个新的幂等键，按钮在该方法返回前保持不可点。界面每秒查询当前任务，并刷新任务列表里的状态，直到当前任务离开 `pending`、`planning`、`generating`。

FFmpeg 不在 PATH 中时，顶栏显示缺少 FFmpeg。此时可以查看已有任务并打开已有成片，不能创建、确认、重生成或重试执行。

## 输入与输出

### 素材

规划只使用已经入库的素材。`asset_id` 是 UUID。

`register_asset` 接受本机文件路径或原始字节，加上文件名和种类（图片或音频）。包把字节写入文件库后才返回 `asset_id`。本版不抓取 HTTP 地址。以后的工作台若持有远程图片，先自行下载，再把字节交给本方法。

图片类型为 JPEG、PNG、WebP。音频为 MP3、WAV、M4A。单文件不超过 20 MB，图片最多 12 张。`config.json` 只能把这两个上限改小。音乐使用的 `asset_id` 必须是已登记音频；创建或修改时类型不对、标识不存在，返回 `VALIDATION_ERROR`，不改变任务。文件在执行时已经丢失，则该执行以 `ASSET_MISSING` 失败，不重新提交视频模型。

创建任务时把 `images` 里的 `asset_id` 绑定到该任务，最多 12 张。`first_frame_asset_id` 只能是其中一张图片。指向不存在的素材、非图片，或不在本次 `images` 中时，抛出字段错误，不创建任务。

### 创建任务

| 字段 | 内容 |
| --- | --- |
| `product_info` | 名称、品类、卖点、规格等。非必填项可缺 |
| `images` | 已登记的产品图片 `asset_id` 列表 |
| `first_frame_asset_id` | 可空。有值表示首帧来源 `selected`；不传或空表示 `generate` |
| `user_prompt` | 用途、受众、风格和其他要求 |
| `video_options` | 时长档位、画面比例，以及字幕、配音、音乐开关 |
| `audio_options` | 语言、配音偏好、音乐描述，或已登记的音频 `asset_id` |
| `external_user_id` | 可选。只随任务保存，不参与授权和去重 |
| `external_request_id` | 可选。只随任务保存。相同值可以重复建任务 |
| `idempotency_key` | 可选。1 到 128 个可见 ASCII 字符 |

`images` 为空时仍然创建任务，状态直接为 `awaiting_input`，不调用规划模型。有图片但看不出可识别的产品外观时，规划结束后进入 `awaiting_input`。这两种情况都不编造产品外观，也不进入首帧生成。

关闭的配音或音乐仍可以带 `audio_options`。执行时忽略对应项，不因此报字段错误。

画面比例、字幕、配音、音乐的默认值是 9:16，三项都开启。调用方可以覆盖。某项为关闭时，跳过对应生成和处理。配音关闭则不调用配音服务；音乐关闭则不调用音乐服务；字幕关闭则不烧录字幕。数据类型错误直接返回字段错误，不进入对话。

时长在调用视频模型之前确定，只能选档，不能填任意秒数。档位由配置注入，每一档都是 1 到 30 的整数秒，含 30。出现大于 30、小于 1、小数、重复或空列表时，进程拒绝使用该配置。默认档位为 5、10、15、30 秒，默认选中 10 秒。默认档必须属于可选档。未传时长时用默认档。传入值不是当前某一档时，返回字段错误，并带上当前档位列表。

自由描述里出现不在档位中的秒数时，不把它当成目标时长，响应里说明当前档位。描述与已选档一致时，按该档规划。方案必须写明所选秒数。要改时长，只能改选另一档并形成新方案版本；确认该版本后，后续生成才用新秒数。已确认方案的秒数在该次执行期间不变。

画面比例预设为 9:16、16:9、1:1、4:5、3:4、4:3、3:2、2:3。其他值返回字段错误，并带上预设列表。模型原生支持该比例时直接生成；否则方案写明 `pad` 或 `crop`。两种都能保住产品主体时，默认提议 `pad`，确认前可以改成 `crop`。禁止拉伸，也禁止导出时改用方案里没有的构图。留边和裁切都保不住主体时，规划进入 `awaiting_input`，并给出仍可用的比例。

结构化字段和自由描述一起构成需求。自由描述可以补充或明确修改已有字段。同一参数的两个明确值无法兼容时，集中问一次。价格、功效、规格、认证和绝对化承诺只使用输入里已经写明的内容。方案可以安排场景、节奏、景别和运镜。

语言未传时，配音和字幕使用产品资料与 `user_prompt` 的主语言。两边主语言冲突，且配音或字幕开启时，进入一次 `awaiting_input`。两者都关闭时不追问语言。

### 导出预设

调用方不提交分辨率、帧率和编码。帧率固定 30。成片为 H.264、yuv420p 的 MP4。有音轨时为 AAC、48 kHz、立体声。默认视频码率 8 Mbps，音频码率 192 kbps。配置可以改码率和下表分辨率，不能改成调用方自由填写。

| 比例 | 尺寸 |
| --- | --- |
| 9:16 | 1080×1920 |
| 16:9 | 1920×1080 |
| 1:1 | 1080×1080 |
| 4:5 | 1080×1350 |
| 3:4 | 1080×1440 |
| 4:3 | 1440×1080 |
| 3:2 | 1620×1080 |
| 2:3 | 1080×1620 |

成片帧数等于已确认秒数乘以 30。镜头边界是半开区间 `[start_frame, end_frame)`，首尾相接，并集为 `[0, total_frames)`。方案同时给出对应秒数。模型片段长于镜头区间时裁到该区间。短于该区间时，该执行以 `SHOT_DURATION_SHORT` 失败。不冻结补帧，也不把短片段当成该档位成品。

### 返回对象

| 对象 | 主要内容 |
| --- | --- |
| 任务 | `task_id`、`status`、`stage`、`failure_scope`、`questions`、`external_user_id`、`external_request_id`、`head_plan_version`、`confirmed_plan_version`、当前执行标识 |
| 方案 | `plan_version`、是否为当前 head、是否已确认、是否已放弃、脚本、分镜、共享视觉设定、帧区间、首帧来源、启用的可选处理、比例适配、模型能力说明 |
| 执行 | `generation_id`、`status`、方案版本、`full` 或 `shots`、镜头标识、基础成品、阶段进度、外部任务号、失败信息 |
| 成品 | `artifact_id`、从 1 递增的版本、对应执行和方案、时长、比例、尺寸、本地文件路径、质量结果 |

`task_id`、`generation_id`、`artifact_id` 和 `asset_id` 都是 UUID。方案版本从 1 递增，编号不重用。尚未发布方案时，`head_plan_version` 为空。它是当前工作方案，不一定是最大编号。它尚未确认时，确认只能指向它。该版本已经确认后，再次确认返回 `STATE_CONFLICT` 和已有 `generation_id`，不新建执行；任务此时通常已经是 `generating`，不能因为状态变了就丢掉这个 `generation_id`。已放弃的草稿可以保留更大编号，仍可按编号读取，但不能确认。被新 head 取代、又没有被放弃的旧未确认版本同样只读，不能确认，也不能再变回 head。`confirmed_plan_version` 在首次确认前为空。`questions` 只在 `awaiting_input` 时有内容，每条说明缺什么。

当前执行标识指向尚未结束的视频执行。没有未结束执行时，指向最新一条视频执行。还没有视频执行时为空。

执行自己的状态取 `queued`、`running`、`succeeded`、`failed`。规划期间任务的 `stage` 为 `planning`。生成期间任务的 `stage` 与当前执行的阶段相同。`failed` 保留失败当时的 `stage`，直到下一次状态写入。其他状态的 `stage` 为空。`completed_shots` 和 `total_shots` 只在生成期间有值。离开 `failed` 时清空 `failure_scope`。

`artifact_path` 返回文件库中的成片路径，供桌面程序打开，也供以后的工作台读取字节。不返回公开临时链接。

## 方案生成与确认

有图片的任务创建后，工人把状态从 `pending` 推进到 `planning`，读取已入库资料和参考图，提取已知事实和视觉特征，生成脚本、分镜和整条视频共享的视觉设定。只有规划成功才发布新版本。规划失败不发布半成品版本。

方案必须包含：

- 整体创意、目标受众、要强调的卖点。
- 共享的产品参考、场景、光线、色调、风格。出现人物时包含人物形象约定。
- 每个镜头的稳定标识、内容、动作、景别、运镜、帧区间和场景标识。标识在同一方案版本内稳定。新版本可以更换标识。
- 开启功能对应的字幕文字、配音文案和音乐方向。关闭的功能不产生执行依赖。
- 所选秒数、各镜头帧数如何加总到该秒数、比例适配，以及所用模型能力和限制。
- 首帧来源。`selected` 写明素材标识。`generate` 写明将在视频创作前生成；方案阶段不产出该图片。

`awaiting_input` 只用于缺必要素材或阻塞性冲突。问题一次返回，带上缺失项和已有内容。非阻塞偏好直接写进方案，确认前再改。

修改有两种：

- 结构化修改：时长档位、比例、适配方式、三个开关、音频选项、首帧、共享视觉设定、镜头内容。校验与创建任务相同。`revise_plan` 在返回前克隆上一版并套用补丁，发布新版本，状态变为 `awaiting_confirmation`。这一路不进入 `pending` 或 `planning`，也不调用规划模型。
- 自然语言修改：返回前把任务写成 `pending`，head 仍是旧版本，并记下这一句。工人再调用规划模型，把那句话解释成上述补丁并发布新版本。它不能把时长改成档位之外的秒数。模型给出阻塞问题时，不发布新版本，状态变为 `awaiting_input` 并写上 `questions`。结果不合法或无法解释时，不发布新版本，任务变为 `failed`，`failure_scope=planning`，`code` 为 `PROVIDER_REJECTED`。临时故障用 `PROVIDER_TEMPORARY`。

结构化补丁只改时长、镜头集合不变、又没有带上全套新帧区间时，按新旧总帧数的比例分配各镜头帧数：先四舍五入，每个镜头至少 1 帧。总和多出来的帧从最长镜头扣除，每个镜头至少留 1 帧；不够的帧加到最长镜头。扣完后仍对不上，或镜头数大于总帧数，返回 `VALIDATION_ERROR`，不发布版本。新增或删除镜头时，补丁必须自带覆盖全部镜头的新帧区间，否则同样是 `VALIDATION_ERROR`。补丁自带帧区间时，必须仍是首尾相接的半开区间，并集为 `[0, 新总帧数)`。只改文案或开关时，不改帧区间。

结构化补丁改比例时，按这次调用读到的视频适配器判断：原生支持则适配方式为原生，否则为 `pad`。补丁显式写了 `pad` 或 `crop` 时以补丁为准。结构化路径不判断裁切能否保住主体；这个判断只在规划模型路径做。确认后的执行只认方案里的适配方式。模型做不到时，该执行以 `PROVIDER_REJECTED` 失败，不另选构图。

把配音或字幕从关改为开时，补丁或上一版里必须已有对应文案。把音乐从关改为开时，必须已有音乐方向或已登记音频。否则返回 `VALIDATION_ERROR`，不发布版本。关闭开关不删除已有文案。要让模型重写文案，走自然语言修改。

初次规划和自然语言修改得到的方案，帧区间不合法、秒数不是该档，或引用了不存在的素材时，不发布版本。这是 `PROVIDER_REJECTED`，`failure_scope=planning`，不是用户的字段错误。自动退避期间保持 `planning` 或原来的生成阶段，不先写成 `failed`；次数用尽后才失败。

每次成功修改产生新的 `plan_version`，旧版本保留。确认必须指定版本，且该版本必须是当前 head。指定已确认旧版本、已放弃版本或其他编号时，返回 `PLAN_VERSION_CONFLICT`，并带上当前 head。

每个方案版本最多确认一次，而且只有它仍是 head、尚未确认、当前状态允许确认时可以确认。确认与执行记录在同一事务中写入：该版本记入 `confirmed_plan_version`，并创建一条视频执行。之后又发布了新 head 时，确认新 head 会再创建一条执行。这是确认，不是重生成。同一幂等键的重放返回当时那条执行。该版本已经确认、但这次请求没有使用当时的幂等键时，返回 `STATE_CONFLICT`，并带上已有的 `generation_id`。

未确认方案不调用视频模型。生成执行绑定不可变快照，包括秒数、帧区间、比例适配、文案和首帧来源。执行期间不接受同任务的方案修改。若当时的模型做不到快照中的时长、比例或参考图方式，该执行以 `PROVIDER_REJECTED` 失败，并写明缺什么能力，不改用另一种构图。

改视觉设定、文案、时长、比例或镜头布局时，先发布新方案并确认，再按新快照生成。未改方案、只想重做画面时，走重生成，沿用 `confirmed_plan_version`。

配音开启时，方案阶段把文案安排进目标时长。生成后若念不完，执行可以在已确认文案和帧区间内调整语速，并随之移动字幕时间。执行不能改文案、镜头边界或总秒数。语速仍放不下时，该执行以 `VOICEOVER_DOES_NOT_FIT` 失败。

## 主体、场景与首帧

分镜共享整条视频的视觉设定。默认同一主体、同一场景保持连续。只有确认方案写明换景时才换场景。改变角度可以带合理的背景视角变化，不能凭空换环境。

1. 所选档位落在模型单段能力之内时，优先一个连续镜头。单段能力不足时，方案里拆成多镜头，各镜头帧数之和等于总帧数。拆分在确认前可见。
2. 多镜头复用产品参考和场景参考，人物、光线、色调、风格和关键道具保持同一约束。
3. 成片第一帧就是该次执行确定的那一张首帧。`selected` 在整条重生成，以及包含第一镜的局部重生成里，仍是成片第一帧。后续镜头的参考图、尾帧或续接按模型能力选择。场景参考全任务共用一份，不为每个镜头单独设计场景。
4. 镜头提示重点写动作、景别和运镜。主体和场景约束来自共享设定。
5. 局部重生成除产品与场景参考外，还使用相邻镜头的边界画面。一次替换多个镜头时按时间顺序生成：左侧邻居若也在本次替换中，用刚生成的结尾帧；右侧邻居不在本次替换中时，用基础成品里的起始帧。只有一个镜头时没有相邻帧，只使用产品和场景参考，并重做这一段的全部画面。

适配层报告模型是否支持首尾帧和参考图。规划器只选择可执行策略。提示词和参考图不能保证绝对一致。某个真实供应商是否可用，用指定首帧的连续镜头样片判断。

### 首帧

每条视频有且仅有一张起始画面，来源在确认前确定。

| 来源 | 条件 | 执行行为 |
| --- | --- | --- |
| `selected` | 方案里有 `first_frame_asset_id` | 直接使用该图片，不调用首帧生成 |
| `generate` | 未指定首帧 | 应先按方案和产品图生成一张首帧并登记，再调用视频模型 |

本版不实现首帧生成，也不调用生图服务。生成执行保留一个边界：输入是已确认方案、用户要求、产品图片和画面比例，输出应为一张已登记图片。该边界当前没有实现。`generate` 在首帧阶段以 `FIRST_FRAME_NOT_IMPLEMENTED` 失败。不能跳过，不能调用视频模型，也不能改用某张产品图充当首帧。`selected` 不依赖该边界。

未指定首帧不等于可以在没有产品图时编造外观。整条重生成沿用已确认方案中的来源：`selected` 继续用原图；`generate` 在边界接入之前仍会同样失败。对这个失败调用 `retry_generation` 返回 `STATE_CONFLICT`，不会跳过首帧去调用视频模型。

能导出成片的调用，必须在本任务图片中指定首帧。桌面程序把「不指定首帧」留成一条可点的验证路径，用来看到上述失败码。

### 质量检查

对每个镜头抽取首、中、尾帧，并检查相邻镜头连接处。检查项为产品形状、主色、识别特征、人物形象，以及场景、光线和风格有没有明显不合理变化。

结果独立于执行状态，取 `passed`、`flagged` 或 `not_assessed`，并附检查项、镜头和原因。`flagged` 的成品仍可打开。检查不能把执行判为失败，也不能代替人看片。抽取的是字幕烧录前的镜头画面，字幕层不算产品外观。未配置检查服务，或服务不可用时，结果为 `not_assessed` 及原因，然后继续导出。未检查不算通过。适配器为 `none` 时仍经过 `checking_visuals`，只是当场记为 `not_assessed`。

## 视频执行与可选处理

确认和重生成在返回前写入执行记录，任务进入 `generating`，阶段为 `queued`，执行状态为 `queued`。有图片的创建任务和自然语言修改，都在返回前写入 `pending`。创建时图片列表为空，直接写入 `awaiting_input`。补充信息按后文决定进入 `pending` 还是留在 `awaiting_input`。结构化修改按上一节在返回前发布新版本。工人只领取已写入的工作。

领取后的顺序：确定首帧，按方案生成镜头，导入已完成的模型结果，按开关准备音频，拼接还没有字幕的画面，做视觉检查，再烧录字幕、混音并导出。首帧或镜头失败时，不调用后续的视频模型、画面拼接或导出。视觉检查不可用只记 `not_assessed`，然后继续导出。

字幕烧进画面，不另挂软字幕轨。字幕使用方案里的字幕文字，配音使用配音文案，两者可以不同。字幕水平居中，底边距为画面高度的 8%，字号为画面高度的 4%，白色填充、2 像素黑色描边。一条字幕超出画面宽度的 84% 时换行；换行后仍放不进画面，或系统里没有能显示该文案的字体时，该执行以 `MEDIA_EXPORT_FAILED` 失败，不用方框字形冒充成功。配音和字幕互不依赖。配音关闭但字幕开启时，字幕按镜头帧区间排列。配音开启时，按实际语音时间对齐，仍限制在已确认帧区间内。烧录发生在视觉检查之后。

背景音乐优先使用调用方已登记的音频，此时不调用音乐接口。没有已登记音频时，才使用已注入的音乐接口。两者都没有且音乐开关为开时，该执行在音频阶段以 `PROVIDER_REJECTED` 失败，不静默变成无音乐。本包不审核音乐版权。调用方提供的音频按原文件使用。音乐裁切或循环到已确认时长，不改变视频时长。配音和音乐同时开启时，有人声的时间段内把音乐音量降为该段原音量的 25%，前后各做 200 毫秒淡变，无人声的区间保持原音量。相邻淡变重叠时，重叠部分取更低的音量。两者都关闭时，`preparing_audio` 不调用外部服务，成片不包含音轨。

`pad` 是等比缩放后放入目标画布，空余填黑。`crop` 是等比放大后居中裁到目标画布。规划器只有在居中裁切仍能保住产品主体时才选择 `crop`。禁止拉伸。

配音开关为开但未注入配音实现时，同样在音频阶段以 `PROVIDER_REJECTED` 失败。替身模式已注入替身配音和替身音乐，因此八种开关组合都可以在替身模式走完。

视频处理层统一帧率、分辨率和编码，按镜头帧区间合成，然后检查文件可解码、帧数、比例，以及音轨是否与开关一致。目标时长按已确认方案，不用模型原始片段时长当作成品时长。

开启且必需的步骤失败时，执行失败，保留已成功的镜头和音频中间结果。不靠关掉字幕、配音或音乐来宣称成功。错误表允许调用方重试时，可对同一条执行从失败阶段继续；不允许重试的失败返回 `STATE_CONFLICT`。也可以修改选项形成新方案后再生成。视觉检查不是这些必需步骤。

整条重生成重做全部镜头画面，并重新执行已开启的配音、音乐和字幕，再合成新成品。局部重生成只替换指定镜头的画面并重新合成。配音、音乐和字幕沿用基础成品，不重新调用这些服务。

每次重生成是一条新执行和一个新成品版本。已有成品仍可打开。「每次一条成品」只限制单次执行的产出条数。

## 任务状态与重生成

| 状态 | 含义 |
| --- | --- |
| `pending` | 已接收，规划尚未开始 |
| `planning` | 正在读素材或生成方案 |
| `awaiting_input` | 需要补充信息，或存在阻塞性冲突 |
| `awaiting_confirmation` | 当前 head 已发布且尚未确认 |
| `generating` | 有一条视频执行在排队或运行 |
| `succeeded` | 最新一条执行已产出可读取成品，且当前 head 就是已确认版本 |
| `failed` | 最新一条规划或视频执行失败。`failure_scope` 为 `planning` 或 `generation` |

非失败状态没有 `failure_scope`。已有成品单独保存，后续执行失败不影响打开它们。任务上的 head 在失败时仍可能是另一版未确认草稿。失败属于哪一版方案，看执行记录上的方案版本。

状态由刚结束的操作写入：

- 规划成功并发布未确认 head 后，为 `awaiting_confirmation`。因缺素材或阻塞冲突停下时，为 `awaiting_input`，不发布方案版本。
- 视频执行成功，且 head 仍是刚执行的那一版已确认方案时，为 `succeeded`。
- 视频执行成功，但 head 已是更新的未确认草稿时，回到 `awaiting_confirmation`。新成品照常进入成品列表。
- 规划或视频执行失败时，为 `failed`。未确认草稿还在时，不把这次失败改写成待确认。

已成功的任务无论是结构化修改，还是自然语言修改并完成规划，都会回到 `awaiting_confirmation`。此状态下的重生成仍使用 `confirmed_plan_version`。这次重生成若失败，状态变为 `failed`，草稿还在 head 上。

常规路径：`pending → planning → awaiting_confirmation → generating → succeeded`。缺素材或阻塞冲突时进入 `awaiting_input`。补充后若已经有图片，先回到 `pending`，再由工人进入 `planning`；图片仍为空则留在 `awaiting_input`。

`stage` 在生成期间取 `queued`、`preparing_first_frame`、`generating_shots`、`preparing_audio`、`composing`、`checking_visuals`、`exporting`。`composing` 只拼接还没有字幕的画面，`checking_visuals` 检查这些画面，`exporting` 再烧录字幕、混音、封装并做成片检查。同时返回 `completed_shots`、`total_shots` 和阶段说明。这两个计数只统计本次执行要生成的镜头。可以附供应商进度原文，不编造百分比。

### 哪些状态接受写入

同一任务同一时间只有一个规划或视频执行。`pending`、`planning`、`generating` 期间，补充、修改、确认、放弃草稿、重生成和另一条重试都返回 `STATE_CONFLICT`。查询始终允许。重复的同一幂等请求返回原记录。

| 状态 | 可接受的写入 |
| --- | --- |
| `awaiting_input` | 补充信息；已有 `confirmed_plan_version` 时还可以放弃这次修改 |
| `awaiting_confirmation` | 修改方案、确认当前 head；已有 `confirmed_plan_version` 时还可以重生成或放弃当前草稿 |
| `succeeded` | 修改方案、整条或局部重生成 |
| `failed` 且 `failure_scope=planning` | 规划重试；从未发布过方案时还可以补充信息；已有 head 时还可以再修改方案；已有已确认版本时还可以放弃这次修改 |
| `failed` 且 `failure_scope=generation` | 该执行重试、整条或局部重生成、修改方案；head 尚未确认时还可以确认该 head 或放弃它 |

补充信息在 `awaiting_input` 接受；规划失败且该任务从未发布过方案时也接受，用来修改原需求。提交的字段按补丁覆盖。`images` 省略表示不改图片，传入空列表表示清空。处理后若图片仍为空，状态为 `awaiting_input`，清空失败，并用 `questions` 说明还缺产品图片。至少有一张合格图片才进入 `pending`，同时清空 `questions`。

规划重试只恢复 `failure_scope=planning`，并且不读取这次调用里的新文案。还没有方案时，重放最后一次创建或补充的需求。失败来自自然语言修改时，重放记下的那一句和当时的 head。要换一句新的修改，调用 `revise_plan`。执行重试只恢复指定的失败执行，并只接受 `retryable=true` 的失败；其他失败返回 `STATE_CONFLICT`，不重新执行。还没有 `confirmed_plan_version` 时，重生成返回 `STATE_CONFLICT`。用错恢复入口时同样返回 `STATE_CONFLICT`。

放弃草稿不创建视频执行，且只在已有 `confirmed_plan_version` 时接受。若 head 尚未确认，放弃后把该版本标为已放弃并保留可读，head 指回已确认版本。若修改尚未发布新版本，放弃只取消这次等待或规划失败。任务状态改回该已确认版本的最新视频执行结果：执行成功则为 `succeeded`，执行失败则为 `failed` 且 `failure_scope=generation`。首个方案还没有已确认版本时，不能放弃，只能补充、修改或确认。

### 重生成语义

| 请求 | 行为 |
| --- | --- |
| 整条重生成 | 绑定最新的 `confirmed_plan_version`，重做全部镜头和已开启的音频处理，合成新成品。不读未确认草稿，不要求镜头标识 |
| 指定镜头重生成 | 指定同一任务里已成功的基础成品，以及该成品方案中的镜头标识。只替换这些画面，复用该成品的配音、音乐和字幕 |
| 失败执行重试 | 沿用该 `generation_id` 已成功的阶段产物，继续未完成阶段。不新建执行。自动重试次数按后文重新计算 |
| 放弃未确认草稿 | 不生成视频。head 回到 `confirmed_plan_version` |

局部重生成若找不到基础成品、镜头标识不属于该成品，或同时要求改时长、镜头布局、场景和文案，返回 `VALIDATION_ERROR`，不创建执行。改时长或镜头布局必须走新方案。改后的时长仍然必须是当前某一档。

局部请求即使包含该成品的每一个镜头，记录仍然是 `shots`，音频仍复用基础成品。它不转换成整条重生成。只有一个镜头时，请求仍要带上该镜头和基础成品。

## Python 接口

以后的 Web 工作台在其 Python 后端里构造 `VideoAgent`，调用下表方法，自己负责页面、登录和权限。本包不依赖请求对象或前端框架。工作台轮询 `get_task` 和 `get_generation`。需要把成片给浏览器时，读取 `artifact_path` 的字节，由工作台自己的接口发出。

耗时步骤由单工人推进。桌面程序启动时先 `recover()`，再循环 `tick()`。工作台进程若嵌入本包，同样如此，或在自己的循环里先 `recover()` 再调用 `tick()`。方法本身在写入任务库后返回，不等待成片。

| 方法 | 作用 |
| --- | --- |
| `list_tasks` | 按更新时间从新到旧列出本地任务，含 `task_id`、状态、产品名称 |
| `register_asset` | 写入字节并返回 `asset_id` |
| `create_task` | 创建任务。有图片则进入 `pending`；无图片则进入 `awaiting_input` |
| `get_task` | 返回状态、阶段、head、已确认版本、当前执行 |
| `submit_inputs` | `awaiting_input`，或规划失败且从未发布方案时。有合格图片则进入 `pending`；图片仍为空则留在 `awaiting_input` |
| `retry_planning` | 重放上一次规划输入，不采纳本次调用里的新文案，保留已导入素材和已发布方案 |
| `get_plan` | 按版本读取方案，包括已放弃版本和已被取代的未确认版本 |
| `revise_plan` | 结构化补丁当场发布新版本。自然语言先进入 `pending`，由工人发布；阻塞或失败时不发布 |
| `discard_revision` | 放弃当前未确认修改，不创建视频执行 |
| `confirm` | 确认当前 head，创建该版本的视频执行 |
| `regenerate` | 创建整条或局部重生成执行 |
| `get_generation` | 查询指定执行 |
| `retry_generation` | 恢复指定的失败执行 |
| `list_artifacts` | 成品从新到旧，含质量结果 |
| `artifact_path` | 返回成片本地路径 |
| `tick` | 领取至多一条到期工作并向前推进一步；无工作时立即返回 |
| `recover` | 启动时恢复租约已过期的任务 |

`create_task`、`submit_inputs`、`revise_plan`、`discard_revision`、`confirm`、`regenerate`、`retry_planning`、`retry_generation` 接受 `idempotency_key`。不传时，每次调用都是一次新操作。作用域是当前数据目录、这一份库和这一个方法。不同方法可以复用同一个字符串。相同方法、相同键、相同参数返回当时的记录，不额外领取规划或视频执行。参数相同指业务参数的规范化 JSON 相同，键顺序无关；幂等键本身不参与比较。相同键但参数不同返回 `IDEMPOTENCY_CONFLICT`。幂等记录与任务状态在同一事务里更新。本版不删除任务，记录与任务一起保留。以后若增加删除，记录不得早于任务删除；若配置保留时间，不得短于 24 小时。`external_request_id` 不是幂等键。

拒绝时抛出 `VideoAgentError`。属性为 `code`、`message`、`stage`、`retryable`，以及适用的任务、执行、字段或镜头标识。查询方法找不到对象时同样抛出，`code` 为 `NOT_FOUND`。桌面程序和以后的工作台都展示 `code`。

## 持久化与故障恢复

SQLite 保存任务、方案版本、执行、镜头、成品、素材引用和幂等记录。方案正文以 JSON 存在该版本的一行里。文件按任务和执行分目录保存。成品先写临时文件，帧数、比例、解码和音轨检查通过后再登记为可打开结果。任务库同一时刻只允许一个写事务。桌面程序的界面线程和工人线程都通过这把锁访问。

`tick` 的一步是下面之一：开始规划、完成规划、确定首帧、提交一个镜头、导入一个已完成镜头、准备音频、拼接无字幕画面、做视觉检查、烧录字幕并导出，或在等待外部任务时续租后返回。等待外部任务时 `tick` 不阻塞到成片完成。工人循环调用 `tick`；没有工作或仍在等待时，休眠 1 秒再调用。

工人用一个事务领取工作：写入执行者标识和 `lease_until`。租约默认 60 秒，不得低于 15 秒。规划、配音、下载等会阻塞的调用，以及等待视频供应商期间，都要续租，间隔不超过租约的一半。只有租约到期后，重新启动的工人才能恢复该任务。租约仍有效时，不把同一步再执行一遍。本版只有一个工人，这条规则用来防止进程崩溃后的重复领取。

检查点包含已确认方案快照、当前阶段、镜头状态、外部任务号和已导入素材。调用视频模型之前，先把本次提交意图和供应商幂等键写入库。恢复时先按该键查询外部任务，再复用本地已成功的阶段产物，最后推进未完成阶段。进程在供应商接受之后、外部任务号写回之前退出时，也按这个顺序核对，不直接再提交一次。

对限流、网络波动和明确的临时故障做退避重试，默认最多追加两次，并尊重供应商给出的等待时间。这个上限属于单个阶段或单个外部操作，存在库里，重启不重置。用户调用执行重试时，才为剩余阶段重新计算。素材缺失、参数不支持、鉴权错误不自动退避。`FIRST_FRAME_NOT_IMPLEMENTED` 和 `VOICEOVER_DOES_NOT_FIT` 也不自动重试，并且调用方不能用重试入口消掉它们。`SHOT_DURATION_SHORT` 视为可退避的供应商结果，仍受上述次数限制。

无法确认外部任务是否已经创建时，标记 `PROVIDER_SUBMISSION_UNCERTAIN`。自动重试和执行重试都只重新查询。查询表明对方没有该任务之后才允许提交。已完成但下载失败时重试下载，不重新生成镜头。

| `code` | 何时使用 | `retryable` |
| --- | --- | --- |
| `VALIDATION_ERROR` | 字段、档位、比例或素材引用不合法 | 否 |
| `NOT_FOUND` | 任务、方案、执行、镜头或成品不存在 | 否 |
| `STATE_CONFLICT` | 当前状态不允许该操作 | 否 |
| `PLAN_VERSION_CONFLICT` | 确认的不是当前 head，或该版本已放弃或已被取代 | 否 |
| `IDEMPOTENCY_CONFLICT` | 同一方法的幂等键已被不同参数使用 | 否 |
| `FIRST_FRAME_NOT_IMPLEMENTED` | 首帧来源为 `generate` | 否 |
| `VOICEOVER_DOES_NOT_FIT` | 已确认文案放不进已确认时长 | 否 |
| `SHOT_DURATION_SHORT` | 模型片段短于方案帧区间 | 是 |
| `ASSET_MISSING` | 已登记素材的文件在执行时不存在 | 是，但不自动退避 |
| `PROVIDER_TEMPORARY` | 可退避重试的供应商或网络故障 | 是 |
| `PROVIDER_REJECTED` | 供应商拒绝参数或鉴权，规划结果不合法，或开启了配音/音乐但没有可用实现 | 是，但不自动退避 |
| `PROVIDER_SUBMISSION_UNCERTAIN` | 无法确认外部任务是否已创建 | 是，但只重新查询 |
| `MEDIA_EXPORT_FAILED` | 合成或字幕结果未通过成片检查 | 是，但不自动退避 |

`retryable=是` 表示调用方可以走对应重试入口。自动退避只用于 `PROVIDER_TEMPORARY`，以及受次数限制的 `SHOT_DURATION_SHORT`。`PROVIDER_SUBMISSION_UNCERTAIN` 的自动重试和执行重试都只查询，查询表明对方没有该任务之后才允许提交。标成「不自动退避」的失败，调用方仍可重试。`retryable=否` 的失败，重试入口返回 `STATE_CONFLICT`。

检查失败和质量偏差分开。前者是执行错误，后者是成品上的 `flagged`。

## 模型接口

本版在包内定义接口，并提供名为 `fake` 的替身实现。视觉检查还可以是 `none`。真实服务通过适配器接入，一次接一套默认组合，不做智能路由。供应商名称和报文不在本文选定。桌面程序的真实模式只负责把 `config.json` 交给已经写好的适配器。效果是否合格，用指定首帧的样片看。

| 接口 | 输入 | 输出 |
| --- | --- | --- |
| 规划 | 产品字段、自由描述、已入库图片、时长档、比例、开关 | 结构化方案；或一组阻塞问题 |
| 规划修改 | 当前方案加一句自然语言 | 结构化补丁，或一组阻塞问题 |
| 视频 | 镜头提示、共享设定、首帧或参考图、帧数、比例、供应商幂等键 | 外部任务号，完成后的视频字节 |
| 配音 | 已确认文案、语言、帧区间 | 音轨和句级时间 |
| 音乐 | 音乐方向或空，目标时长 | 音轨。调用方已给音频时不调用 |
| 视觉检查 | 字幕烧录前的关键帧和方案中的外观描述 | `passed`、`flagged` 或不可用原因 |

视频接口必须能查询异步任务。提交前写入的供应商幂等键要能用来找回已创建的任务。

替身视频只把 9:16 视为原生比例，并按镜头帧数产出以首帧或参考图为画面的可解码片段。其他比例走方案里的 `pad` 或 `crop`，合成、帧数和音轨检查在没有密钥时仍然真实执行。替身默认足帧，不用来制造 `SHOT_DURATION_SHORT`；这个错误用测试里的短片段替身验证。替身不代表产品还原已经通过。

真实样片在桌面程序的真实模式下做。素材用包装商品、服饰配饰、数码家电或家居中的代表图，指定首帧，覆盖准备启用的时长档、单镜头、多镜头同场景、有意换场景和局部重生成。某一档超过单段能力时，只能以确认前可见的多镜头拆分交付。记录产品外观、人物和场景是否随镜头漂移。样片不通过时换适配器或调整生成策略，不改本文的状态和确认规则。

## 验收

用桌面测试程序做人工验证。另外用替身模型做不打开窗口的流程测试，避免每改一次状态规则都手点界面。两类验证都调用同一个 `video_agent`。替身通过只说明流程和成片封装通过。

1. 固定字段和自由描述可以一起提交。缺少一般偏好时先出方案，不做多轮非必要追问。输入里没有的价格、功效、规格、认证和绝对化承诺不写进方案。
2. 未确认方案时不调用视频生成。确认只能作用于当前尚未确认的 head，并创建该版本唯一的一条执行。同一幂等键重放返回该执行。不带原幂等键的再次确认返回 `STATE_CONFLICT` 和已有 `generation_id`。旧版本、已放弃版本和已被取代的未确认版本返回 `PLAN_VERSION_CONFLICT`。规划结果的帧区间不合法时不发布版本。
3. 在桌面程序里指定一张本任务产品图为首帧后，可以完成选图、改方案、确认、看到进度，并打开一条帧数等于已确认秒数乘以 30 的成片。不指定首帧时，确认仍会创建执行，但在调用视频模型前以 `FIRST_FRAME_NOT_IMPLEMENTED` 失败，底部展示该 `code`。
4. 替身模式下，字幕、配音、音乐的八种开关都能走完。关闭项不调用对应实现。配音和音乐都关闭时，成片没有音轨。两者都开启时，有人声的区间音乐为原音量的 25%。
5. 替身模式下，9:16 按原生尺寸导出，至少一种其他比例按已确认的 `pad` 或 `crop` 导出。成片可解码，尺寸符合导出预设，字幕和音轨与开关一致。
6. 时长只接受配置档位。自由描述中的非档位秒数不会变成目标时长。超过 30 秒的档位无法加载。非法配置不会改写原来的 `config.json`。只改时长档时，新方案的镜头帧数之和等于新秒数乘以 30。
7. 整条重生成不要求镜头标识，并重新执行已开启的音频处理。局部重生成保留未指定画面和基础成品音轨，产生新成品，旧成品仍可打开。镜头标识不合法的局部请求不创建执行。
8. 有检查实现时，镜头内部和连接处都会检查。明显漂移为 `flagged`，成片仍可打开。未配置检查时为 `not_assessed`，执行仍可成功。
9. 失败使用上表 `code`，并带阶段和上下文字段。桌面程序显示这些字段。
10. 临时故障最多追加两次，退避期间任务仍处于原来的进行中状态。中断后恢复复用已成功结果，租约未到期时不把同一步再执行一遍。外部提交状态不明时不盲目创建第二条外部任务。规划失败和视频失败走各自的重试入口。`retryable=否` 的失败不能靠重试入口再跑一遍。从未发布方案的规划失败，可以改需求后重新规划。
11. 已有已确认版本时，可以放弃尚未确认的 head，且不会因此新建视频执行。有执行在跑时，修改、确认和再次生成都返回 `STATE_CONFLICT`，对应按钮不可点。
12. 真实模式在配置了服务之后，用指定首帧完成至少一条成片，并用人看产品主体和场景是否连续。这一条不阻塞替身流程的通过，但在更换默认视频适配器时必须重做。

## 实现顺序

1. 核心包的类型、状态规则、SQLite 和文件库。
2. 替身规划与替身视频，打通指定首帧后的确认、生成、合成和成片检查。
3. 桌面测试程序走通这条路径，包括未指定首帧时的失败码。
4. 八种开关、重生成、重试、放弃草稿和租约恢复。
5. 供应商选定后再实现那一家的规划适配器和视频适配器，并在桌面真实模式里出指定首帧样片。未选定前不写真实报文，替身验收不因此停住。
6. 首帧生成边界保持未实现，等视频链路稳定后再对接 imageAgent。

Web 工作台不在上述顺序里。核心包方法稳定之后，由接入方在自己的后端调用。
