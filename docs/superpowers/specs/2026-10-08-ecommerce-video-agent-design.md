审阅修订：2026 年 10 月 9 日  
阶段：初稿，已被定稿取代。

定稿见 `docs/superpowers/specs/2026-10-09-ecommerce-video-agent-design.md`。实现以定稿为准。定稿保留本文的生成、确认和状态规则，把交付收成 Python 核心包加桌面测试程序，HTTP 与 Web 工作台改由后续接入。

本文修正了状态机、确认、重生成和本版首帧范围中的冲突。模型服务需要在选型阶段通过真实样片验证。

## 项目目标与范围

开发一个 Python 电商视频生成 Agent，接收产品信息、图片和用户需求，通过大模型规划内容，再调用视频生成服务产出宣传或其他用途的视频。后续由 Python 后端和 Vue 前端接入。

本项目交付 Python 核心包 `video_agent` 及同一仓库内的薄 HTTP 接口层。两种调用方式使用同一套业务逻辑、状态规则和数据结构。Web 页面、登录与业务权限、费用展示和预算控制由接入方负责。Agent 按输入开关执行字幕、配音和背景音乐处理，不承担成本管理。

本版能够导出成片的调用，必须在本任务图片中指定首帧（`selected`）。未指定首帧时仍按后文保留 `generate` 边界；该边界未接入 imageAgent 前，执行会在调用视频模型之前失败。样片和成片验收都走指定首帧，不把未实现的首帧生成算进视频模型能力。

### 已确认的第一版需求

| 项目 | 约定 |
| --- | --- |
| 视频形式 | 以 AI 生成新的动态画面为核心 |
| 商品品类 | 支持多种品类，不限制为单一品类；效果分品类验证 |
| 视频时长 | 生成前从可配置档位中选择整数秒，确认方案后按该秒数生成；不能填写任意秒数，任一档不超过 30 秒 |
| 画面比例 | 调用方可以选择主流比例 |
| 成品数量 | 每次生成执行产出一条完整视频 |
| 产品还原 | 主要外观和识别特征保持一致，允许轻微细节偏差 |
| 跨镜头连续性 | 主体、场景、光线和风格保持连贯；换场景必须在已确认方案中明确 |
| 人工确认 | 先生成脚本与分镜，允许修改，确认指定方案版本后再生成视频 |
| 文字输入 | 同时支持结构化产品字段和自由描述 |
| 补充信息 | 默认少追问，先给合理方案；关键阻塞或无法兼容的冲突才集中询问 |
| 可选处理 | 字幕、配音、背景音乐分别开启或关闭 |
| 重新生成 | 同时支持整条重生成和指定镜头重生成 |
| 接入方式 | Python 包及 HTTP 接口 |
| 默认存储 | SQLite 保存记录，本地目录保存素材和视频，预留替换接口 |
| 模型服务 | 尚未选定，通过适配层接入，依据能力和样片结果选择 |
| 视频首帧 | 用户可以指定一张已上传图片作为首帧，也可以不指定；不指定时先按需求生成首帧，再创作视频。首帧生成本版只留调用边界，后续对接 imageAgent |

“每次一条成品”不限制后续重生成次数。每次重生成形成一个新版本，已有成品仍可访问。

## Agent 架构

采用受控 Agent：关键阶段、确认节点和持久化行为由程序控制，模型负责语义理解、创意规划、自然语言修改及受约束的工具参数生成。编排库在实施计划中选定。任务、方案版本、幂等、租约和外部任务号以本项目的任务仓库为准，不交给模型框架的会话内存。

状态变更规则只写在核心包内。进程内调用方和配套执行器都调用这些规则。HTTP 层只做校验、鉴权和持久化入队。

| 模块 | 对外职责 | 主要依赖 |
| --- | --- | --- |
| Agent 核心 | 创建和修改方案，确认方案，执行单次规划或视频步骤，维护合法状态变更 | 模型接口、任务仓库、视频处理接口 |
| 模型适配层 | 产品理解、脚本规划、视频生成、配音和视觉检查等能力 | 外部服务 SDK 或 API |
| 视频处理层 | 处理镜头、音轨、字幕、比例与成品导出 | 媒体处理工具，初版使用 FFmpeg |
| 任务与素材管理 | 保存任务、方案、执行记录、外部任务标识和成品版本 | SQLite、文件存储接口 |
| 执行器 | 领取已持久化的工作，续租，调用核心步骤，恢复中断任务 | Agent 核心、任务仓库 |
| HTTP 接口层 | 验证请求结构，调用核心的同步校验，把耗时工作写入仓库后返回 | Agent 核心、任务仓库 |

核心包不依赖 HTTP 请求对象、Vue、具体 Web 登录体系，也不依赖执行器进程。更换视频模型或对象存储时，核心调用契约保持稳定。模型、媒体处理、任务仓库和素材存储均通过明确的 Python 接口注入。

第一版可使用 Pydantic 定义输入输出，FastAPI 提供 HTTP 接口。具体版本与依赖在实施计划中锁定。HTTP 请求处理与耗时生成分离。确认、重生成和规划一旦写库成功，单任务锁就生效，不以进程内临时任务列表作为记录。

默认 SQLite 部署只运行一个执行器进程。同一仓库上的多个执行器进程属于替换仓库之后的部署，不在默认 SQLite 实现里承诺。

## 输入与输出约定

### 素材登记

规划只使用已经入库的素材引用。`asset_id` 是 UUID。HTTP `POST /v1/assets` 接受上传文件，或接受经过校验的 HTTP / HTTPS 地址；字节写入本地存储之后才返回 `asset_id`。获取失败时该请求失败，不创建规划任务。HTTP 不接受服务器本地路径。Python 包可以把调用方本地文件复制进存储后再返回引用。

远程地址只允许 `http` 和 `https`。连接前检查解析结果，拒绝环回、链路本地、私有网段和云元数据地址；每次重定向都重新检查，最多跟随 3 次。单文件不超过 20 MB，获取超时 20 秒。图片类型为 JPEG、PNG、WebP。调用方提供的音乐为 MP3、WAV 或 M4A，上限同样是 20 MB。部署配置只能把大小、张数和超时改小，不能关闭地址范围检查。

创建任务时把 `images` 里的 `asset_id` 绑定到该任务。一个任务最多绑定 12 张产品图。`first_frame_asset_id` 只能是其中一张图片。

### 创建任务的输入

| 字段 | 内容 |
| --- | --- |
| `product_info` | 产品名称、品类、卖点、规格等结构化信息；非必填字段允许缺省 |
| `images` | 已登记的产品图片 `asset_id` 列表，可含不同角度和细节图 |
| `first_frame_asset_id` | 可选。指定 `images` 中的一张作为视频首帧；不传、空值或显式清空都表示首帧来源为 `generate` |
| `user_prompt` | 自由描述的视频用途、受众、风格和特别要求 |
| `video_options` | 所选时长档位、画面比例，以及字幕、配音、音乐开关 |
| `audio_options` | 启用相关功能时的语言、配音偏好、音乐描述或已有音频 `asset_id` |
| `external_user_id` | 接入方用户或主体标识，只随任务保存，不参与授权，也不参与去重 |
| `external_request_id` | 接入方业务关联标识，只随任务保存。相同值可以重复创建任务 |

本项目以产品图片作为主体参考。`images` 为空时仍然创建任务，但直接进入 `awaiting_input`，不调用规划模型。图片已上传、却看不到可识别的产品外观时，规划结束后进入 `awaiting_input`。这两种情况都不编造产品外观，也不进入首帧生成。产品文字资料少时，优先根据已有素材提出展示方案，避免要求用户填满字段。

`first_frame_asset_id` 指向不存在的素材、非图片，或不在本次 `images` 中时，直接返回字段错误，不创建任务。确认前可以通过方案修改改指定另一张，或改为不指定。已确认方案快照中的首帧来源在该次执行期间不变。

关闭的配音或音乐仍可以附带 `audio_options`，执行时忽略对应项，不因此返回字段错误。

画面比例、字幕、配音和音乐的便捷默认值为 9:16，三项均开启；调用方可明确覆盖。开关为 `false` 时，跳过对应素材生成和处理。配音关闭时不调用配音服务，音乐关闭时不调用音乐服务，字幕关闭时不烧录字幕。请求结构校验与业务信息追问分开：错误的数据类型直接返回字段错误，不触发对话。

时长在调用视频生成之前确定，并且只能选择，不能填写任意秒数。可选档位由部署配置注入，每一档都是 1 到 30 之间的整数秒，包含 30 秒。配置里出现大于 30 秒、小于 1 秒、小数、重复或空档位时，服务拒绝加载该配置。初版建议档位为 5、10、15、30 秒，默认 10 秒；默认档必须属于可选档位。调整配置可以增删 30 秒以内的档位，不能把时长改成自由填写，也不能加入超过 30 秒的档位。未传时长时使用默认档。传入值不是当前某一档时，直接返回字段错误，并附上当前可选档位，不进入方案对话。

自由描述里出现不在档位中的秒数时，不把它当成有效时长，也不按该秒数规划；同一次响应说明当前可选档位。描述与已选档位一致时，按该档位规划。方案必须写明所选秒数。调用方要改时长时，只能改选另一档并形成新的方案版本；确认该版本之后，后续生成才使用新秒数。已确认方案的秒数在执行期间不变。

画面比例采用可扩展预设，初版覆盖 9:16、16:9、1:1、4:5、3:4、4:3、3:2、2:3。传入预设之外的值时返回字段错误，并附上当前预设。输出比例与视频模型原生比例分开处理：原生支持时直接生成；否则方案写明 `pad` 或 `crop`。两种都能保住产品主体时，方案默认提议 `pad`，调用方可在确认前改成 `crop`。适配必须保留产品主体，不允许拉伸，也不允许在生成后改用方案里没有的构图。连留边和裁切都无法保住主体时，规划进入 `awaiting_input`，并给出仍可用的比例选项。

结构化字段和自由描述共同构成需求。自由描述可以补充和明确修改已有字段。同一个参数的两个明确值无法兼容时，提出一次集中问题。价格、功效、规格、认证和绝对化承诺只采用输入资料里已经写明的内容；方案可以安排的是场景、节奏、景别和运镜。

语言未传时，配音和字幕使用产品资料与 `user_prompt` 的主语言。两边主语言判断冲突，且配音或字幕开启时，进入一次 `awaiting_input`。两者都关闭时不追问语言。

### 导出预设

调用方不提交分辨率、帧率和编码。初版帧率固定为 30。成片为 H.264、yuv420p 的 MP4；存在音轨时为 AAC、48 kHz、立体声。默认视频码率 8 Mbps，音频码率 192 kbps。部署配置可以改码率和下表分辨率，不能改成调用方自由填写。

| 比例 | 初版尺寸 |
| --- | --- |
| 9:16 | 1080×1920 |
| 16:9 | 1920×1080 |
| 1:1 | 1080×1080 |
| 4:5 | 1080×1350 |
| 3:4 | 1080×1440 |
| 4:3 | 1440×1080 |
| 3:2 | 1620×1080 |
| 2:3 | 1080×1620 |

成片帧数等于已确认秒数乘以 30。镜头边界用帧序号表示，区间为半开的 `[start_frame, end_frame)`，首尾相接，并集等于 `[0, total_frames)`。方案同时给出对应秒数，便于展示。模型片段长于镜头区间时裁到该区间；短于该区间时该执行失败，不冻结补帧，也不把短片段当成该档位成品。

### 返回的主要对象

| 对象 | 主要内容 |
| --- | --- |
| 任务 | `task_id`、`status`、`stage`、`failure_scope`、`external_user_id`、`external_request_id`、`head_plan_version`、`confirmed_plan_version`、当前执行标识 |
| 方案 | `plan_version`、是否为当前 head、是否已确认、是否已放弃、脚本、分镜、共享视觉设定、帧区间、首帧来源、启用的可选处理、比例适配方式、模型适配说明 |
| 执行记录 | `generation_id`、`status`、使用的方案版本、`full` 或 `shots`、镜头标识、基础成品、阶段进度、外部模型任务标识、失败信息 |
| 成品 | `artifact_id`、从 1 递增的成品版本、对应执行和方案、时长、比例、尺寸、文件引用、质量检查结果 |

方案版本从 1 递增，编号不重用。`head_plan_version` 是当前工作方案，不一定是最大编号。它尚未确认时，确认请求只能指向它；它已经确认时，再次确认不会新建执行。已放弃的草稿可以保留更大编号，仍可按编号读取，但不能确认。`confirmed_plan_version` 在首次确认前为空。

Python 调用可取得文件位置和元数据。HTTP 返回成品标识，以及需要同一服务鉴权的 `GET /v1/artifacts/{artifact_id}/download`。该接口直接返回视频字节，不返回公开的临时链接，也不暴露服务器绝对路径。接口使用 `/v1` 版本前缀，响应字段保持可扩展。

## 方案生成与确认

有图片的任务创建后，执行器把状态从 `pending` 推进到 `planning`，读取已入库的产品资料与参考图，提取已知产品事实和视觉特征，生成脚本、分镜以及整条视频共享的视觉设定。新的方案版本只在规划成功时发布。规划失败不发布半成品版本。

方案需能够直接用于前端展示和后续执行，包括：

- 整体创意、目标受众、重点表达的卖点。
- 共享产品参考、场景、光线、色调、风格；出现人物时包含人物形象约定。
- 每个镜头的稳定标识、内容、动作、景别、运镜、帧区间和场景标识。镜头标识在同一方案版本内稳定；新方案版本可以更换标识。
- 开启功能对应的字幕文字、配音文案和音乐方向；关闭功能不产生执行依赖。
- 所选时长档位、各镜头帧数如何加总到该秒数、比例适配方式，以及可用模型能力和关键限制。
- 首帧来源：`selected` 时写明素材标识；`generate` 时写明将在视频创作前生成，方案阶段不产出该图片。

方案阶段允许 `awaiting_input`，但只用于必要素材缺失或阻塞性冲突。问题集中返回，包含缺失项和已有内容，便于调用方一次收集答案。非阻塞的偏好直接形成建议，用户在方案确认阶段修改即可。

调用方可提交结构化方案修改，也可提交自然语言修改要求。结构化修改是对时长档位、比例、三个开关、音频选项、首帧、共享视觉设定和镜头内容的局部更新，校验规则与创建任务相同。自然语言修改先解释成上述变更，再发布新版本；它不能把时长改成档位之外的秒数。修改产生新的 `plan_version`，旧版本保留。确认请求必须指定版本，而且该版本必须是当前 head。指定已确认过的旧版本、已放弃版本或其他编号时返回 `PLAN_VERSION_CONFLICT`，并带上当前 head。

每个方案版本最多确认一次，而且只有它仍是 head、尚未确认、当前状态也允许确认时可以确认。确认与执行记录在同一事务中写入：该版本记入 `confirmed_plan_version`，并创建一条视频执行。之后又发布了新 head 时，确认新 head 会再创建一条执行；这仍然是确认，不是重生成。同一幂等键的重放返回当时那条执行。该版本已经确认、但这次请求没有使用当时的幂等键时，返回 `STATE_CONFLICT`，正文带上已有的 `generation_id`，不新建执行。

首次调用视频生成服务以某版方案已经确认为前置条件。生成执行绑定不可变的已确认方案快照，包括秒数、帧区间、比例适配、文案和首帧来源。执行期间不接受同任务的方案修改。执行按快照做；若当时的模型已经做不到快照中的时长、比例或参考图方式，该执行以 `PROVIDER_REJECTED` 失败并写明缺失的能力，不改用另一种构图。

调整视觉设定、文案、时长、比例或镜头布局时，先发布新方案并确认，再按新快照生成。未改方案、只想重做画面时，走重生成，沿用 `confirmed_plan_version`。

配音开启时，方案阶段把文案安排进目标时长。生成后若念不完，执行可以在已确认文案和帧区间内调整语速，并随之移动字幕时间。执行不能改文案、镜头边界或总秒数。语速仍无法放入时，该执行以 `VOICEOVER_DOES_NOT_FIT` 失败；调用方等执行结束后再修改方案。

## 主体与场景连续性

分镜共享整条视频的视觉设定，而不是各自独立构造产品和环境。默认同一主体、同一场景保持连续；只有确认方案明确指定场景切换时，才进行换景。改变拍摄角度允许出现合理的背景视角变化，不允许凭空换环境。

### 生成策略

1. 所选档位落在模型单段能力之内时，优先采用单个连续镜头。单段能力不足时，在方案中拆成多镜头，各镜头帧数之和等于已选档位对应的总帧数；拆分方式在确认前可见。
2. 多镜头复用产品参考和场景参考，并保持人物、光线、色调、风格和关键道具约束一致。
3. 视频的第一帧来自该次执行确定的那一张首帧。用户指定时使用该图片；未指定时使用执行阶段生成的首帧。`selected` 在整条重生成，以及包含第一镜的局部重生成里，都仍然是成片第一帧。后续镜头的其余参考图、尾帧或视频续接仍按模型能力选择。需要建立场景参考时，采用统一参考并随任务保存，不能为每个镜头重新独立设计场景。
4. 镜头提示中重点指定动作、景别和运镜变化；已确定的主体及场景约束来自共享设定。
5. 局部重生成除使用产品和场景参考外，还使用相邻镜头的边界画面作为衔接参考。一次替换多个镜头时按时间顺序生成：左侧邻居若也在本次替换中，用刚生成的结尾帧；右侧邻居不在本次替换中时，用基础成品里的起始帧。只有一个镜头时没有相邻帧，只使用产品和场景参考，并重做这一段的全部画面。

首尾帧或参考图并非每个模型都支持。适配层报告实际能力，规划器选择可执行策略。提示词、参考图和视觉检查都不能承诺绝对一致性。供应商是否适合此项目，必须用真实连续镜头样片验证。

### 质量检查

对每个镜头抽取首、中、尾关键帧，并检查相邻镜头连接处。检查项包括产品形状、主色、识别特征，人物形象，以及场景、光线和风格是否出现明显不合理变化。

产品包装小字的完全准确复刻不作为本版承诺，但明显影响产品识别的 Logo 或包装变化需标记。文字卖点优先使用可选字幕层呈现，避免依赖视频模型生成精准文字。关闭字幕时不烧录字幕层；模型画面里偶然出现的字形不算字幕。

检查结果独立于执行状态，使用 `passed`、`flagged` 或 `not_assessed`，并附检查项、相关镜头和原因。`flagged` 的成品仍然可以下载。自动视觉检查是辅助判断，不能代替用户最终确认，也不能把执行判为失败。检查服务不可用时返回 `not_assessed` 及原因，不能将未检查当作通过。

## 视频执行与可选处理

确认和重生成在返回前写入执行记录，任务进入 `generating`，阶段为 `queued`。创建任务、补充信息和方案修改在返回前写入 `pending`。图片列表为空时直接写入 `awaiting_input`，不进入 `pending`。执行器只领取这些已写入的工作，不补写初始记录。领取后先确定首帧，再按方案生成镜头，导入已完成的模型结果。随后按开关生成或加载音频、烧录字幕，并合成、导出成品。任一前置阶段失败时，不调用后续的视频模型或合成。

### 首帧

每条视频都有且仅有一张起始画面，来源在确认前确定：

| 来源 | 条件 | 执行行为 |
| --- | --- | --- |
| `selected` | 创建或修改方案时给出 `first_frame_asset_id` | 直接使用该已上传图片，不调用首帧生成 |
| `generate` | 未指定首帧 | 按已确认方案、用户要求和产品图片生成一张首帧，登记为任务素材后，再开始视频创作 |

未指定时，首帧生成发生在确认之后、第一次调用视频生成之前。生成结果随本次执行保存。整条重生成沿用已确认方案中的来源：`selected` 继续使用原图；`generate` 重新生成首帧，不复用上一次生成图，除非该次执行是失败重试且首帧已经成功。

产品图片仍然只证明商品外观。未指定首帧不等于可以在没有产品图时编造外观。

本版不实现首帧生成，也不在本仓库调用生图服务。这里只保留一个由执行器调用的边界：输入是已确认方案、用户要求、产品图片和画面比例，输出是一张已登记图片。实现留空。后续由同级目录的 imageAgent（Python 包 `image_agent`）填入该边界，视频 Agent 不复制它的选图、提示词和审核流程。边界未接入时，`generate` 路径在首帧阶段以 `FIRST_FRAME_NOT_IMPLEMENTED` 失败。不能跳过该步骤，不能调用视频模型，也不能改用某张产品图充当首帧。`selected` 路径不依赖该边界。

### 声音、字幕与合成

字幕烧录进画面，默认放在底部安全区内，不另挂软字幕轨。配音和字幕的启用状态互不依赖：配音关闭但字幕开启时，字幕按镜头文案和帧区间排列；配音开启时，按实际语音时间对齐，仍限制在已确认帧区间内。

背景音乐可通过音乐提供接口获取，也可使用调用方已登记的音频。音乐能力可以由素材库或生成服务实现；实际来源、素材引用和执行结果随任务记录。适配层的具体实现与视频模型一起在选型阶段确定。本项目不审核音乐版权，调用方提供的音频按原文件使用。音乐裁切或循环到已确认时长，不改变视频时长。配音和音乐同时开启时，有人声的区间降低音乐。两者都关闭时，成片不包含音轨。

视频处理层负责统一帧率、分辨率和编码，保证目标比例，按镜头帧区间合成画面与音轨，最后检查文件可解码、帧数、比例和音轨是否与开关一致。目标时长按已确认方案执行，不把模型原始片段时长直接当作成品时长。

任一开启且必需的步骤失败时，执行返回失败，保留已成功的镜头和音频中间结果；不静默关闭字幕、配音或音乐来宣称成功。可通过同一条执行的重试继续未完成阶段，或明确修改选项形成新方案后生成新版本。视觉检查不在这些必需步骤里。

整条重生成会重新生成全部镜头画面，并重新执行已开启的配音、音乐和字幕，再合成新成品。局部重生成只替换指定镜头的画面并重新合成；配音、音乐和字幕沿用基础成品，不重新调用这些服务。

## 任务状态与重生成

### 任务状态

| 状态 | 含义 |
| --- | --- |
| `pending` | 任务已接收，规划尚未开始 |
| `planning` | 正在读取素材、理解需求或生成方案 |
| `awaiting_input` | 存在必要的补充信息或阻塞性冲突 |
| `awaiting_confirmation` | 当前 head 已发布且尚未确认 |
| `generating` | 已有一条视频执行在排队或运行 |
| `succeeded` | 最新一条执行已产出可读取成品，且当前 head 就是已确认版本 |
| `failed` | 最新一条规划或视频执行失败；`failure_scope` 为 `planning` 或 `generation` |

`succeeded` 只表示当前 head 就是已确认版本，且最新一条视频执行已经成片。质量结果写在成品上。非失败状态没有 `failure_scope`。`failed` 保留失败阶段和 `failure_scope`。已有成品单独保存，后续执行失败不影响它们下载。失败属于哪一版方案，看执行记录里的方案版本；任务上的 head 这时仍可能是另一版未确认草稿。

状态由刚结束的那次操作写入，而不是只看 head 是否已确认：

- 规划成功并发布未确认 head 后，状态为 `awaiting_confirmation`。规划因缺素材或阻塞冲突停下时，为 `awaiting_input`，不发布方案版本。
- 视频执行成功，且 head 仍是刚执行的那一版已确认方案时，状态为 `succeeded`。
- 视频执行成功，但 head 已是更新的未确认草稿时，状态回到 `awaiting_confirmation`。新成品照常进入成品列表。
- 规划或视频执行失败时，状态为 `failed`。未确认草稿是否还在，不把这次失败改写成待确认。

因此，已成功的任务提交修改并完成规划后，会回到 `awaiting_confirmation`。此状态下的重生成仍使用 `confirmed_plan_version`。这次重生成若失败，状态变为 `failed`，草稿还在 head 上。

常规路径为 `pending → planning → awaiting_confirmation → generating → succeeded`。缺素材或阻塞冲突时进入 `awaiting_input`，补充后回到 `planning`。

阶段进度返回 `stage`、`completed_shots`、`total_shots`、时间戳及阶段描述。`completed_shots` 和 `total_shots` 只统计本次执行要生成的镜头。可附供应商真实进度，不人为制造精确百分比。生成阶段的取值为 `queued`、`preparing_first_frame`、`generating_shots`、`preparing_audio`、`composing`、`checking_visuals`、`exporting`。

### 哪些状态接受写入

同一任务同一时间只有一个规划或视频执行。`pending`、`planning`、`generating` 期间，补充、修改、确认、放弃草稿、重生成和另一条重试都返回 `STATE_CONFLICT`。只读查询始终可调用。重复的同一幂等请求返回原记录。

| 状态 | 可接受的写入 |
| --- | --- |
| `awaiting_input` | 补充信息；已有 `confirmed_plan_version` 时还可以放弃这次修改 |
| `awaiting_confirmation` | 修改方案、确认当前 head；已有 `confirmed_plan_version` 时还可以重生成或放弃当前草稿 |
| `succeeded` | 修改方案、整条或局部重生成 |
| `failed` 且 `failure_scope=planning` | 规划重试；已有已确认版本时还可以放弃这次修改 |
| `failed` 且 `failure_scope=generation` | 该执行重试、整条或局部重生成、修改方案；head 尚未确认时还可以确认该 head 或放弃它 |

补充信息只在 `awaiting_input` 接受。规划重试只恢复 `failure_scope=planning` 的失败。执行重试只恢复指定的失败执行。还没有 `confirmed_plan_version` 时，重生成返回 `STATE_CONFLICT`。用错恢复入口时同样返回 `STATE_CONFLICT`。

放弃草稿不创建视频执行，且只在已有 `confirmed_plan_version` 时接受。若 head 是尚未确认的版本，放弃后把该版本标为已放弃并保留可读，head 指回已确认版本。若修改尚未发布新版本，放弃只取消这次等待或规划失败。任务状态改回该已确认版本的最新视频执行结果：执行成功则为 `succeeded`，执行失败则为 `failed` 且 `failure_scope=generation`。首个方案还没有已确认版本时，不能放弃，只能补充、修改或确认。

不同任务由后台执行器按配置排队。具体并发量由服务部署配置决定，不改变公开接口。

### 重生成语义

| 请求 | 行为 |
| --- | --- |
| 整条重生成 | 绑定最新的 `confirmed_plan_version`，重做全部镜头画面和已开启的音频处理，合成新成品；不读取未确认草稿，也不要求镜头标识 |
| 指定镜头重生成 | 指定同一任务里已成功的基础成品和该成品方案中的镜头标识，只替换这些画面，复用该成品的配音、音乐和字幕，再合成新成品 |
| 失败执行重试 | 沿用该 `generation_id` 已成功的阶段产物，继续失败或未完成阶段。自动重试次数按后文重新计算。不新建一条执行 |
| 放弃未确认草稿 | 不生成视频。head 回到 `confirmed_plan_version` |

局部重生成若找不到基础成品、镜头标识不属于该成品，或调用方同时要求改时长、镜头布局、场景和文案，返回 400 `VALIDATION_ERROR`，不创建执行记录。改时长或镜头布局必须走新的方案版本。改后的总时长仍然必须是当前配置中的某一档。

局部请求即使包含该成品的每一个镜头，记录仍然是 `shots`，音频仍复用基础成品。它不转换成整条重生成。只有一个镜头时，画面结果会覆盖整条视频，请求仍要带上该镜头和基础成品。

## Python 与 HTTP 接口草案

### 核心调用能力

核心包提供创建任务、登记素材、规划、修改、补充信息、确认、放弃未确认草稿、执行、查询、重生成、失败重试及读取成品等能力。耗时步骤提供可等待的异步方法。服务模式下 HTTP 不调用这些等待方法，只把工作写入仓库并返回。

Python 调用方可以自行驱动异步执行，也可以启用配套执行器。两种方式都使用同一份任务仓库和状态变更规则。

创建、确认和重生成接受幂等键。HTTP 使用请求头 `Idempotency-Key`，取值为 1 到 128 个可见 ASCII 字符，作用域是当前服务凭据加路由。相同键、相同路由、相同正文返回原记录，HTTP 状态与首次成功时相同；相同键但正文不同返回 `IDEMPOTENCY_CONFLICT`。Python 方法使用同名参数，作用域是进程内调用方。幂等记录与任务状态在同一事务里更新。记录保留到任务记录删除为止；若部署配置了保留时间，不得短于 24 小时。`external_request_id` 不是幂等键。

### HTTP 端点

| 方法与路径 | 成功状态 | 用途 |
| --- | --- | --- |
| `POST /v1/assets` | 201 | 导入并登记素材，返回 `asset_id` |
| `POST /v1/tasks` | 202；图片列表为空时为 200 | 创建任务。有图片时安排方案生成；没有图片时进入 `awaiting_input` |
| `GET /v1/tasks/{task_id}` | 200 | 查询状态、阶段、head、已确认版本及当前执行 |
| `POST /v1/tasks/{task_id}/inputs` | 202 | 补充必要信息并继续规划 |
| `POST /v1/tasks/{task_id}/retry` | 202 | 恢复失败的规划，保留已导入素材和已发布方案 |
| `GET /v1/tasks/{task_id}/plans/{version}` | 200 | 获取指定方案版本，包括已放弃版本 |
| `POST /v1/tasks/{task_id}/plan-revisions` | 202 | 提交结构化或自然语言修改，安排新方案生成 |
| `POST /v1/tasks/{task_id}/plan-revisions/discard` | 200 | 放弃当前方案修改，不创建视频执行 |
| `POST /v1/tasks/{task_id}/confirm` | 202 | 确认当前 head，创建该版本的视频执行 |
| `POST /v1/tasks/{task_id}/regenerations` | 202 | 创建整条或局部重生成执行 |
| `GET /v1/tasks/{task_id}/generations/{generation_id}` | 200 | 查询指定视频执行状态与结果 |
| `POST /v1/tasks/{task_id}/generations/{generation_id}/retry` | 202 | 恢复失败执行 |
| `GET /v1/tasks/{task_id}/artifacts` | 200 | 按版本从新到旧列出成品，含质量结果 |
| `GET /v1/artifacts/{artifact_id}/download` | 200 | 下载成品字节 |

方案尚未发布时，202 响应里的新版本号留空，调用方查询任务取得 `head_plan_version`。创建执行的 202 响应包含 `task_id` 和 `generation_id`。补充信息的正文携带缺失字段、说明，或已经登记的新 `asset_id`；新图片的绑定规则与创建任务相同。

字段错误返回 400 `VALIDATION_ERROR`。未找到任务、方案、执行、镜头或成品返回 404 `NOT_FOUND`。状态不允许、用错重试入口返回 409 `STATE_CONFLICT`。方案版本不符合确认条件返回 409 `PLAN_VERSION_CONFLICT`。幂等键冲突返回 409 `IDEMPOTENCY_CONFLICT`。

HTTP 服务默认供后端调用。业务用户权限由接入方验证。服务监听非回环地址时必须配置 `Authorization: Bearer` 服务凭据；仅监听回环地址的本地开发可以不启用。鉴权失败返回 401 `UNAUTHORIZED`，不进入业务逻辑。素材和成品下载使用同一服务鉴权。

第一版使用轮询获取进度和结果。Webhook、WebSocket、计费和前端管理页面不属于本版交付范围。

## 持久化与故障恢复

SQLite 保存任务、方案版本、执行记录、镜头记录、成品、素材引用及幂等记录。文件按任务和执行分目录保存。成品先写入临时位置，帧数、比例、解码和音轨检查通过后再登记为可访问结果。

执行器用单个事务领取到期工作：写入执行者标识和 `lease_until`，避免两个过程领取同一任务。租约默认 60 秒，不得配置到 15 秒以下。等待供应商期间也要续租，续期间隔不超过租约的一半。只有租约到期后，重启的执行器才恢复该任务。

检查点包含已确认方案快照、当前阶段、镜头状态、外部任务标识以及已导入素材。调用视频模型之前，先把本次提交意图和供应商幂等键写入仓库。恢复时先按该键查询外部任务，再复用本地已成功的阶段产物，最后推进未完成阶段。进程在供应商接受之后、外部任务号写回之前退出时，也按这个顺序核对，不直接再提交一次。

对限流、网络波动和明确的临时服务故障采用退避重试，默认最多追加两次，尊重供应商的重试时间。这个上限属于单个阶段或单个外部操作，持久化保存，重启不重置，用户调用执行重试时才为剩余阶段重新计算。素材缺失、参数不支持、服务鉴权错误等直接失败。`FIRST_FRAME_NOT_IMPLEMENTED` 和 `VOICEOVER_DOES_NOT_FIT` 不自动重试。镜头时长不足视为可重试的供应商结果，仍受上述次数限制。

无法确认外部任务是否已经创建时，标记 `PROVIDER_SUBMISSION_UNCERTAIN`。自动重试和执行重试都只重新查询，查询表明对方没有该任务之后才允许提交。已完成但下载失败时重试下载，不重新生成镜头。

错误结构包括 `code`、`message`、`stage`、`retryable`、任务与执行标识，以及适用的字段或镜头标识。检查失败和质量偏差分开表达：前者是执行错误，后者是成品上的 `flagged`。

| `code` | 何时使用 |
| --- | --- |
| `VALIDATION_ERROR` | 字段、档位、比例或素材引用不合法 |
| `UNAUTHORIZED` | 服务鉴权未通过 |
| `NOT_FOUND` | 任务、方案版本、执行、镜头或成品不存在 |
| `STATE_CONFLICT` | 当前状态不允许该操作 |
| `PLAN_VERSION_CONFLICT` | 确认的不是当前 head，或该版本已放弃 |
| `IDEMPOTENCY_CONFLICT` | 幂等键已被不同正文使用 |
| `FIRST_FRAME_NOT_IMPLEMENTED` | 首帧来源为 `generate`，且边界尚未接入 |
| `VOICEOVER_DOES_NOT_FIT` | 已确认文案无法放进已确认时长 |
| `SHOT_DURATION_SHORT` | 模型片段短于方案帧区间 |
| `PROVIDER_TEMPORARY` | 可退避重试的供应商或网络故障 |
| `PROVIDER_REJECTED` | 供应商拒绝参数或鉴权 |
| `PROVIDER_SUBMISSION_UNCERTAIN` | 无法确认外部任务是否已创建 |
| `MEDIA_EXPORT_FAILED` | 合成结果无法通过成片检查 |

## 模型选型与验收

### 选型方法

文本规划模型需要理解产品图片及资料，输出结构化脚本和分镜，遵守共享视觉设定，并支持自然语言修改。视频模型重点验证产品主体还原、场景连续性、参考图能力、可用时长与比例，以及异步任务查询和恢复能力。配音、音乐及视觉检查分别通过能力接口接入，可以来自不同服务。

用户曾简单接触名为“织梦”的服务，具体平台需核实，不能据此认定供应商已选定。第一版选择一套通过验证的默认服务组合，架构支持替换；不在本版实现多个供应商的智能路由。

用包装商品、服饰配饰、数码家电或家居用品的代表素材进行验证，同时测试准备启用的时长档位、单连续镜头、多镜头同场景、有意换场景和局部重生成。样片必须指定首帧。某一档超过模型单段能力时，只能以确认前可见的多镜头拆分交付，不能在生成后把不足的片段当成该档位成品。记录实际能力与缺陷，尤其观察产品外观、人物和场景是否随镜头漂移。多品类支持是输入和流程要求，不等同于所有品类生成质量一致。

### 验收标准

1. 固定字段和自由描述可共同提交；缺少一般偏好时可以先生成方案，不进行多轮非必要追问。事实性卖点、规格和认证缺少来源时不写入方案。
2. 未确认方案时不调用视频生成服务。确认只能作用于当前尚未确认的 head，并创建该版本唯一的一条执行。同一幂等键重放返回该执行；不带原幂等键的再次确认返回 `STATE_CONFLICT` 和已有 `generation_id`。旧版本和已放弃版本返回 `PLAN_VERSION_CONFLICT`。
3. 指定本任务产品图为首帧后，可完成提交素材、方案修改、确认生成、查询状态，并获取一条帧数等于已确认秒数乘以 30 的成品。未指定首帧时，确认仍会创建执行，但在视频模型调用前以 `FIRST_FRAME_NOT_IMPLEMENTED` 失败。
4. 在指定首帧的任务上，字幕、配音和音乐八种开关组合均能执行。关闭项不调用对应服务，不进入对应处理；配音和音乐都关闭时成片没有音轨。
5. 主流比例按原生生成或方案里已确认的 `pad` / `crop` 输出，结果可解码，尺寸符合导出预设，字幕和音轨与开关一致。
6. 时长只接受配置档位中的整数秒，拒绝任意填写；超过 30 秒的档位无法加载。方案展示所选秒数。自由描述中的非档位秒数不会被当成目标时长。
7. 整条重生成不要求镜头标识，并重新执行已开启的音频处理。局部重生成保留未指定画面和基础成品的音轨，产生新成品，已有成品保留。不符合基础成品镜头布局的局部请求不创建执行。
8. 主体与场景检查覆盖镜头内部和镜头连接处。明显漂移记为 `flagged`，成品仍可下载。检查不可用时为 `not_assessed`，执行仍可成功。
9. Python 与 HTTP 对同一输入给出一致的方案、状态和结果结构。失败原因使用上表编码，并带阶段和上下文字段。
10. 临时故障最多追加两次；中断恢复复用成功结果；幂等重放和外部提交状态不明时不盲目创建第二条外部任务。规划失败和视频执行失败走各自的重试入口。
11. 通过多品类、指定首帧的真实样片审阅产品主体还原和场景连续性，并覆盖准备启用的时长档位。单一服务不能满足时，调整选型或生成策略后重新验证。
12. 已有已确认版本时，可以放弃尚未确认的 head，且不会因此新建视频执行。有执行在跑时，修改、确认和再次生成都返回 `STATE_CONFLICT`。

接口、状态、幂等、功能开关和故障恢复使用可控模型替身验证。真实模型联调用于确认外部能力、成片质量及跨镜头一致性。替身验证通过不代表真实视频质量已通过。

## 后续交付顺序

接口约定、状态和本文中的默认值以此修订稿为准。下一步做服务选型与样片验证，把结果补进设计，再制定实现计划。Agent 核心、HTTP 接口和视频执行的代码在这些步骤之后进行。首帧生成保持空边界，待视频执行链路稳定后对接 imageAgent，不与本版视频模型选型绑在一起。
