# Video Agent API 与 MySQL Implementation Plan

实施状态：用户已于 2026-10-14 明确授权按本计划使用多个 agent 开发并创建数据库表。执行记录见 `.agent-runs/2026-10-14-api-mysql/`；保留现有未提交改动，不创建 Git 节点，不正式迁移用户旧数据。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Subagent-driven execution is optional only if the user explicitly chooses it. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 复用当前视频 Agent，为外部调用方提供 HTTP API，把模型配置、任务和供应商任务记录统一存入本机 MySQL。

**Architecture:** FastAPI 处理认证、HTTP 校验和路由；VideoAgent 保持唯一业务状态机；独立 Worker 使用 MySQL 工作表和租约执行长任务。数据库配置与加密快照确保修改配置不会切换正在运行任务的模型，媒体文件继续存本地。

**Tech Stack:** Python 3.11+、Pydantic v2、FastAPI、Uvicorn、SQLAlchemy Core、PyMySQL、Alembic、cryptography、Pillow、pytest、HTTPX、FFmpeg/ffprobe、MySQL 8.0+。

**Spec:** `docs/superpowers/specs/2026-10-14-api-mysql-design.md`，草案；与本计划一起审阅。

## Global Constraints

- 用户已明确授权实施代码、安装开发依赖以及创建所需数据库表；使用独立测试数据库验收。
- 开发与验收进行中；完成状态以执行记录及最终验收报告为准。
- 模型配置和任务数据都存本机 MySQL；默认主机 `127.0.0.1`、端口 `3306`、数据库名 `video_agent`，实施前只读核实；不能覆盖已有同名业务库。
- 密码不写进文档、源码、示例或日志；数据库密码、HTTP Token 和 `VIDEO_AGENT_SECRET_KEY` 由环境变量提供。
- Python 3.11+、Pydantic v2、MySQL 8.0+、InnoDB、utf8mb4；默认 HTTP 监听 `127.0.0.1:8000`。
- 初版一台机器、一个 Worker、多请求客户端；业务调用方共享一套任务空间，external_user_id 不作为权限凭证。
- API 前缀 `/api/v1`；分页默认 limit=20、最大 100、offset 最小 0；Idempotency-Key 为 1～128 个可见 ASCII 字符。
- 在线文档固定提供 `/docs`（Swagger UI）、`/redoc`（ReDoc）、`/openapi.json`；中文说明与真实路由/模型自动同步，JS/CSS 随服务本地提供。
- 保留先规划后确认生成、方案版本、整体/镜头重生成、重试、提交不确定和恢复行为；不增加取消或删除任务。
- 工作快照与历史配置修订中的密钥同样加密；运行时按快照构造适配器，禁止改写共享实例。
- 外部模型请求和 FFmpeg 在数据库事务外执行；测试不调用真实付费供应商。
- 首版文件仍存本地，同一 MySQL 对应同一文件根目录；源 SQLite、JSON 和媒体文件保留。
- 工作区已有修改；不覆盖无关内容、不创建 Git 节点。每任务的提交步骤改为只读审查，除非用户另行授权。

## Review Focus

- 并发相同幂等键和确认请求：一个业务结果，同键不同 payload 必须 409（Task 1、5）。
- 租约失效后旧 Worker 返回结果：拒绝写回且不抢占新持有者（Task 3）。
- 配置更新、删除或重启：已提交/不确定的视频任务仍使用原快照及原任务号（Task 2、3、4）。
- 从 home 与仓库根目录找到不同 config.json：仅使用明确指定来源；重复导入冲突回滚（Task 4）。
- 超限上传、未知 ID、越界文件路径、无权访问和包含密钥的上游错误：明确状态码、无泄漏、无遗留工作项（Task 5、6）。
